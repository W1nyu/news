# 아침 경제

네이버 경제 8개 섹션에서 발행 시각이 확인된 무료 기사를 선별하고, 날짜별 요약·검색·헤드라인·북마크와 같은 사건을 묶은 관련 보도를 제공합니다. 수집·요약 발췌에 모델 API를 사용하지 않습니다.

## 실행

처음 설치: `python -m pip install -r requirements.txt`

- 뉴스 수집: `python scripts/collector.py` (오늘) / `python scripts/collector.py --date 2026-09-12` (어제·그제)
- 웹 서버: `python scripts/server.py`
- 수집 후 화면 열기: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_daily_briefing.ps1 -Open`
- 예약·바로가기 설치: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install_daily_task.ps1` (제거는 `-Uninstall`)

주소는 **http://127.0.0.1:8765/** 입니다. 버전 쿼리는 필요 없습니다. 서버가 루트 HTML을 매번 제공하고 CSS·JavaScript 내용에 맞는 버전 식별자를 붙입니다. `python -m http.server` 대신 위 서버를 사용해야 수집 버튼이 작동합니다.

## 선별 기준

| 네이버 섹션 | 번호 | 최종 기사 한도 | 후보 확인 한도 |
|---|---|---:|---:|
| 금융 | 259 | 9 | 60 |
| 증권 | 258 | 9 | 60 |
| 산업/재계 | 261 | 9 | 60 |
| 부동산 | 260 | 9 | 60 |
| 글로벌 경제 | 262 | 9 | 60 |
| 경제일반 | 263 | 9 | 60 |
| 중기/벤처 | 771 | 9 | 60 |
| 생활경제 | 310 | 9 | 60 |

모든 섹션 최소 목표는 3건, 섹션당 최대 9건(총 최대 72건)입니다. 같은 사건을 다룬 기사는 새 카드가 아니라 대표 기사의 관련 보도로 묶이므로, 9건은 서로 다른 사건으로 채워집니다. 후보 목록은 네이버 섹션 첫 페이지(36건)에 이어 다음 페이지를 후보 확인 한도(60건)까지 읽습니다. 다음 페이지를 받지 못하면 그때까지 모은 후보로 진행합니다. `config/sections.json`에서 한도·72시간 범위·캐시 유효기간·보관함 색인 기간(`archive_days`, 기본 90일)을 수정합니다. 검증 통과 후보가 부족하면 `data/run-status.json`에 `shortfall`로 기록합니다. 후보 목록에서 목표 수를 채우면 본문 접근을 중단합니다.

**키워드 설정** 메뉴에서 키워드를 추가·수정·삭제하고 **설정 저장**을 누르세요. 로컬 `config/keywords.json`에 영구 저장되며 다음 수집부터 적용됩니다. 가중치는 -100~100 정수이며 최대 100개입니다. 제목에 포함된 키워드마다 한 번씩 점수를 합산합니다(대소문자 무시). 높은 점수부터 검증하고 동점은 네이버 목록 순서를 유지합니다. 음수는 완전 제외가 아닙니다. 메뉴 분류는 네이버 섹션을 그대로 사용합니다.

무료 본문·발행 시각 검증을 통과한 기사만 남깁니다. 수정일이나 URL을 발행일로 추정하지 않습니다. 미래 기사·72시간 이전 기사·유료 기사·미확인 기사는 제외합니다. URL과 동일 제목을 중복 제거하며, 먼저 처리한 섹션에 배정합니다. 사이트 구조나 유료 표시가 바뀌면 수집기를 점검해야 합니다. 제목의 글자 2-gram 유사도가 0.45 이상이고 숫자·방향어(상승/하락 등)가 어긋나지 않으면 같은 사건으로 보고 먼저 선택된 기사의 관련 보도로 묶습니다. 한도를 채운 뒤에는 이미 선택된 기사와 비슷한 제목만 섹션당 최대 8건 더 확인합니다.

## 화면

- **2단 읽기**: 너비 1024px 이상에서는 왼쪽에 섹션별 제목 목록, 오른쪽에 고른 기사의 상세(요약·관련 보도·버튼)가 나옵니다. 상세 영역과 섹션 탭은 스크롤해도 따라옵니다. 기사를 고르기 전 오른쪽에는 헤드라인과 섹션별 안 읽은 수가 보입니다. 좁은 창에서는 목록에서 고른 행 아래에 상세가 펼쳐집니다.
- **헤드라인**: 현재 보고서에서 키워드 점수가 높은 순(동점은 최신순) 6건. 누르면 섹션·검색어·언론사 필터를 해제하고 그 기사를 고릅니다.
- **읽음**: 기사를 상세로 보거나 원문을 열면 읽음으로 표시됩니다(목록의 점이 사라지고 흐려짐). 상세의 **안 읽음으로** 버튼이나 `m`으로 되돌립니다. 섹션 탭 숫자는 안 읽은 기사 수, 묶음 머리의 **모두 읽음**은 그 묶음을 한 번에 읽음 처리합니다.
- **안 읽은 것만**: 켜면 읽은 기사를 숨깁니다. 방금 읽은 기사는 섹션·날짜·검색어를 바꿀 때까지 목록에 남아 갑자기 사라지지 않습니다. 저장함에는 적용하지 않습니다.
- **저장함**: 상세의 **☆ 저장**(`s`)으로 저장한 기사가 날짜 역순으로 모입니다. 미수집 날짜를 선택한 상태에서도 열 수 있습니다.
- **링크 복사**: 상세의 **링크 복사**(`c`)는 `제목 (언론사)`와 다음 줄의 원문 링크를 클립보드에 복사합니다.
- **키보드 단축키**: `j`/`↓` 다음, `k`/`↑` 이전, `Enter`/`o` 원문, `s` 저장, `c` 복사, `m` 읽음 전환, `u` 안 읽은 것만, `0` 전체·`1`~`8` 섹션·`9` 저장함, `/` 검색, `Esc` 선택 해제, `?` 도움말. 입력창에 글을 쓰는 중에는 동작하지 않습니다.
- **보기 메뉴**: 앱바의 **보기**에서 테마(라이트·다크·시스템, 기본 라이트)와 글자 크기(작게·보통·크게)를 고릅니다.
- **키워드 강조**: 제목과 요약에서 내 키워드와 일치한 부분에 배경색을 표시합니다.
- **관련 보도**: 같은 사건을 다룬 다른 언론사 기사는 대표 기사 상세에 `관련 보도 n건`으로 붙습니다(기사당 최대 4건, 목록에는 `관련 n`). 관련 기사도 무료·발행 시각 검증을 통과한 것만 붙습니다.
- **최근 7일 모아보기**: 날짜 목록에서 고르면 최근 7일 보고서를 합쳐(같은 기사는 한 번만) 섹션별 키워드 점수 순으로 보여줍니다.
- **기사 수 추이**: 제목 오른쪽의 작은 막대는 최근 14일 보고서별 기사 수입니다. 마우스를 올리면 섹션별 건수가 보입니다.
- **기간·언론사 필터**: 검색 중에는 발행일 기준 기간(최근 7일/30일/직접 입력)을, 모든 화면에서 언론사를 골라 볼 수 있습니다.
- **오늘 보고서 없음 배너**: 서버 기준 오늘 날짜 보고서가 없으면 상단에 안내와 수집 버튼이 나타납니다.
- **미수집 날짜**: 날짜 목록의 `(미수집)` 항목(오늘·어제·그제 중 보고서가 없는 날)을 고르면 그 날짜 기사만 골라 보고서를 만들 수 있습니다. 그 날짜의 네이버 섹션 목록(섹션당 후보 한도까지)에서 고르며, 3일이 지난 날짜는 수집할 수 없습니다.
- **스타일**: 당근 SEED 디자인 토큰(`dist/tokens.css`, 브랜드 색만 딥그린)과 `dist/app.css`. 모바일(<768px)은 고정 상단바·가로 스크롤 섹션 탭·바텀시트 설정 화면입니다.
- **브라우저 저장**: 읽음·저장함·안 읽은 것만·테마·글자 크기는 이 브라우저의 localStorage에만 저장되며 다른 기기와 공유되지 않습니다.

## 매일 운영

`install_daily_task.ps1`은 작업 두 개와 바탕화면 바로가기를 만듭니다.

- `Daily Economy Briefing`: 매일 07:30 수집. 놓친 경우 가능한 한 빨리 실행(StartWhenAvailable).
- `Daily Economy Briefing (Logon)`: 로그인 1분 후 `data/오늘.json`이 없을 때만 수집. PC가 꺼져 있던 날도 로그인만 하면 보고서가 생깁니다.
- 바탕화면 **아침 경제 수집**: 더블클릭하면 지금 수집하고, 서버가 없으면 띄운 뒤 화면을 엽니다.

한 번 실행하면 JSON·날짜별 검색 색인이 함께 갱신됩니다. 기사별 검사 결과를 30분 캐시하므로 짧은 간격으로 반복 실행해도 같은 본문을 다시 읽지 않습니다(따라서 키워드를 바꾼 직후 재수집하면 30분 안에는 요약 문장 선택이 그대로일 수 있습니다). 예약·바로가기 실행 결과는 `logs/collector.log`에 남습니다. 자동·수동·웹 수집 간 잠금으로 중복 실행을 방지합니다. 전체 실패 시 이전 보고서를 보존합니다. 같은 날짜 재실행은 그 날짜 보고서를 갱신하고 다른 날짜는 유지합니다. `latest.json`은 항상 보관함에서 가장 최신 날짜의 보고서입니다.

종료 코드: 0 성공, 1 검증 통과 기사 없음, 2 다른 수집 실행 중, 3 수집 불가 날짜.

주요 파일: `data/run-status.json` (운영 확인), `logs/collector.log` (예약 실행 기록), `data/progress.json` (수집 중 진행률, 완료 시 삭제), `data/latest.json` (최신 보고서), `dist/data/search.json` (보관함 검색 색인). 날짜 목록·검색·7일 모아보기·14일 막대는 가장 최신 보고서 기준 최근 `archive_days`일(기본 90일)만 다루며, 그보다 오래된 날짜별 JSON 파일은 삭제하지 않고 남겨 둡니다. 이전 다중 출처 자료는 파일로 보존하되 새 화면의 보관함에는 섞지 않습니다.

요약은 본문 문장 발췌입니다. 첫 문장(리드)과, 제목·내 키워드·수치와 가장 연관된 문장 하나를 고릅니다(제목 연관 발췌). API 기반 재작성·투자 의견 생성은 하지 않습니다. 운영 에이전트는 **AGENTS.md**의 짧은 실행 절차를 따르세요.

검증: `python -m unittest discover -s scripts -p "test_*.py"`, `node --check dist/app.js`, `node --test scripts/test_app.cjs` (날짜 전환·저장함·헤드라인·안 읽은 수·단축키·기본 테마 회귀 검사).
